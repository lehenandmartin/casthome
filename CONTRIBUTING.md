# Contributing

Issues and pull requests are welcome. For anything larger than a fix, open an
issue first to talk it through. See [How it works](docs/how-it-works.md) for
the architecture.

## Development

Requirements: Python 3.12, Node 20+.

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e "backend[dev]"
cd frontend && npm install && cd ..
```

Run the backend (it stores its data in `./data`, reads an optional `.env` at
the repository root from any directory, and serves the built frontend from
`frontend/dist`, so run `npm run build` after frontend changes) and, for
frontend work, the Vite dev server, which proxies `/api` to it:

```bash
.venv/bin/python -m casthome.main
```

```bash
cd frontend && npm run dev
```

This is also how to run CastHome on macOS or Windows, where Docker's host
network does not carry Cast discovery.

## Tests and checks

Backend: tests, lint with ruff, types with mypy (add `--cov=casthome` to
pytest for a coverage report):

```bash
cd backend && ../.venv/bin/python -m pytest && ../.venv/bin/ruff check casthome tests && ../.venv/bin/mypy casthome
```

Frontend:

```bash
cd frontend && npm test && npm run check && npm run build
```

End to end: the real backend serves the built interface (`npm run build`
first) against a fake Subsonic server ([`frontend/e2e/fake_subsonic.py`](frontend/e2e/fake_subsonic.py)),
in headless Chromium, on a phone and on a desktop. It plays on *This
browser*, so no Cast device is needed. Once, install the browser:
`cd frontend && npx playwright install chromium`. Then:

```bash
cd frontend && npm run e2e
```

Every push runs all of these on GitHub Actions; the Docker image is only
published when they pass.

Errors in the interface (uncaught exceptions, rejected promises) are sent to
the server and written to its log as `casthome.client` warnings, with the
page and the browser: useful to see what went wrong on a phone.

## Translations

UI text never goes in components: add each string to `lib/i18n/en.ts` and its
translations to `lib/i18n/fr.ts`, `de.ts` and `es.ts` (`npm run check` fails if
one is missing).

## Releases

The version is `__version__` in `backend/casthome/__init__.py` (the API and
**Settings → About** report it); `frontend/package.json` carries the same
number.
Every push to `main` that passes the checks publishes the `:main` image (GitHub Actions,
[`.github/workflows/docker.yml`](.github/workflows/docker.yml)). To release:

1. Run the [device checklist](docs/device-checklist.md) (real browsers,
   phones and Cast devices: what the tests cannot see).
2. Set `__version__` to the new version (e.g. `0.4.0`), do the same in
   `frontend/package.json` (`cd frontend && npm version 0.4.0
   --no-git-tag-version`), and commit.
3. Tag and push: `git tag v0.4.0 && git push origin main v0.4.0`.
4. Publish the GitHub release with its notes (what changed, for users):
   `gh release create v0.4.0 --title "CastHome 0.4.0" --notes-file notes.md`,
   or from the *Releases* page.

The workflow checks the tag matches `__version__`, then publishes `:0.4.0`,
`:0.4`, `:0` and `:latest`. The release notes are the changelog: there is no
`CHANGELOG.md`.

## Implementation notes

- **Covers** are converted by CastHome to WebP at the size each page shows
  (about 4 to 6 times lighter than the server's originals) and kept in
  `<data>/covers` (capped at 300 MB, least recently used first).
  Each one is checked against the server after 7 days and converted again
  only if it changed; browsers keep them for a day.
- **Live updates:** while playing, browsers get an update only when something
  changed, not on every status poll; long lists only lay out the rows near
  the screen.
- **Service worker:** it only caches the app shell (HTML, JS, CSS, icons); the
  API and the WebSocket always go to the server. Icons are generated by
  `python3 scripts/make_icons.py`.
- **Installed iOS app:** internal links go through a small client-side router
  (`history.pushState`), because an installed iOS web app may otherwise
  reload the whole page on each link tap. The last known player, queue and
  device list are kept in `localStorage` and shown instantly at startup, then
  replaced by the server's state once the WebSocket opens (cleared on
  sign-out). The "Reconnecting…" notice only appears after 3 s without a
  connection.

## Layout

```
backend/casthome/
  __init__.py          __version__ (the only place to change it)
  config.py            optional environment settings
  appconfig.py         configuration saved from the browser, access modes,
                       CastHome password hashing, encryption key file
  db.py                SQLite + migrations
  auth/                sessions, encrypted music server password
  subsonic/            Subsonic client, token URLs, Cast format policy
  cast/                discovery (zeroconf), pychromecast adapter,
                       browser.py: a browser tab driven like a Cast device
  queue/logic.py       pure queue logic (next/previous/shuffle/repeat/move)
  playback/            coordinator state machine, media payloads, persistence
  scrobble/            scrobbling rules
  api/                 REST routers (setup.py first-run setup, server.py
                       settings), WebSocket endpoint, stream.py (audio proxy)
  ws/hub.py            WebSocket broadcast and per-tab messages
frontend/src/
  lib/i18n/en.ts            every UI string, in English (the default)
  lib/i18n/fr.ts, de.ts, es.ts  French, German and Spanish (same keys, checked by the compiler)
  lib/i18n/lang.svelte.ts   language choice (automatic or per device)
  lib/store.svelte.ts       app state, WebSocket client, startup cache
  lib/router.svelte.ts      hash routing without page loads
  lib/browserPlayer.ts      <audio> player for "This browser", Media Session
  lib/icons.ts              SVG icon set
  lib/contextMenu.svelte.ts the action menu (⋯ sheet or right-click), shown by
                            components/ContextMenu.svelte
  lib/menus.ts              menu entries for tracks, queue, albums, playlists,
                            artists
  components/               UI (PlayerBar, NowPlaying, QueueView, DevicePicker…)
frontend/public/            manifest, service worker, icons
scripts/make_icons.py       regenerates the PWA icons
```
